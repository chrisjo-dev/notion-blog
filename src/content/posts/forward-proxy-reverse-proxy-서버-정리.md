#Infra #IaaS #개념 #Proxy


## 1. **프록시 서버란?**

- 클라이언트와 서버 사이에서 **대리 역할**을 하는 중간자 서버.
- 요청과 응답을 직접 전달하지 않고, **프록시 서버가 대신 처리**.
- 보안, 성능 최적화, 접근 제어, 부하 분산 등의 목적에 활용.

---


## 2. **종류와 대표 기술**


### (1) **포워드 프록시 (Forward Proxy)**

- **클라이언트 앞에 위치** → 외부로 나가는 요청을 대신 처리.

### 쓰는 이유

- 보안/익명성 (실제 클라이언트 IP 숨김)
- 접근 제어 (조직에서 특정 사이트 차단)
- 캐싱 (자주 요청되는 콘텐츠 빠른 제공)
- 대역폭 절감

### 대표 기술 / 제품

- **Squid Proxy** → 가장 대표적인 오픈소스 포워드 프록시
- **Apache HTTP Server (mod_proxy)** → 프록시 기능 지원
- **Blue Coat ProxySG** (기업용 상용 솔루션)
- **Zscaler Internet Access (ZIA)** (클라우드 기반 보안 프록시)

---


### (2) **리버스 프록시 (Reverse Proxy)**

- **서버 앞에 위치** → 외부로 들어오는 요청을 대신 처리.

### 쓰는 이유

- 로드 밸런싱 (여러 서버로 트래픽 분산)
- 보안 강화 (실제 서버 구조/주소 은닉)
- SSL 종료 (TLS 암호화 처리)
- 캐싱 (정적 파일 제공 속도 향상)
- 고가용성 (Failover 지원)

### 대표 기술 / 제품

- **Nginx** → 가장 많이 쓰이는 오픈소스 리버스 프록시
- **Apache HTTP Server (mod_proxy, mod_ssl)**
- **F5 BIG-IP LTM** (대형 엔터프라이즈 로드밸런서)
- **AWS ALB (Application Load Balancer)**
- **Cloudflare** (CDN + 리버스 프록시)

---


## 3. **비교 요약**


| 구분       | 포워드 프록시 (Forward)                           | 리버스 프록시 (Reverse)                                       |
| -------- | ------------------------------------------- | ------------------------------------------------------- |
| 위치       | 클라이언트 앞단                                    | 서버 앞단                                                   |
| 누구를 대리?  | 클라이언트                                       | 서버                                                      |
| 트래픽 방향   | 아웃바운드 (내부 → 외부)                             | 인바운드 (외부 → 내부)                                          |
| 주요 목적    | 익명성, 접근 제어, 캐싱, 대역폭 절감                      | 로드밸런싱, 보안, SSL 종료, 고가용성                                 |
| 대표 기술/제품 | Squid, Apache mod_proxy, Zscaler, Blue Coat | Nginx, Apache mod_proxy, F5 BIG-IP, AWS ALB, Cloudflare |


```python
[클라이언트] → (포워드 프록시) → 인터넷 → [서버]
   (내부망에서 나갈 때)

[클라이언트] → 인터넷 → (리버스 프록시) → [서버]
   (외부 요청이 들어올 때)
```


---


핵심:

- **포워드 프록시**는 **내부 사용자 제어/보안용**
- **리버스 프록시**는 **외부 트래픽 분산/보안용**
- **위치는 본질적으로 같음** → 클라이언트와 서버 사이.
- **다만 역할/관점이 다름** → 누구를 대신하느냐에 따라 명칭이 달라짐.
    - 클라이언트를 대신 → 포워드 프록시 (아웃바운드)
    - 서버를 대신 → 리버스 프록시 (인바운드)
