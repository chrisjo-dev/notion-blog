#Infra #IaaS #개념


| 용어                            | 일반 인프라 관점                    | 온프레미스(OpenStack/KVM)                        | 클라우드(AWS/EKS/ECS)                           | 워크로드 예시                                        |
| ----------------------------- | ---------------------------- | ------------------------------------------- | ------------------------------------------- | ---------------------------------------------- |
| **서버 (Server)**               | 물리 하드웨어, CPU·RAM·Disk·NIC 보유 | Dell/HPE 등 베어메탈 서버                          | AWS EC2 인스턴스 (가상 서버)                        | 하드웨어 자체, 아직 앱은 없음                              |
| **노드 (Node)**                 | 역할이 부여된 서버 단위                | Controller Node, Compute Node               | EKS Worker Node, ECS Task, Control Plane 노드 | “이 서버는 Compute 전용”처럼 역할 지정                     |
| **컨트롤러 (Controller)**         | 클러스터 “두뇌”, 관리/조정             | Keystone, Glance, Neutron-Server, Scheduler | AWS EKS/ECS Control Plane (AWS 관리)          | 앱 직접 실행 안 함. 대신 “이 워크로드는 Compute 3번에서 돌려”라고 지시 |
| **컴퓨트 (Compute)**             | 실제 워크로드 실행기                  | OpenStack Nova-Compute (VM 실행)              | EC2 인스턴스, ECS Task, EKS Worker Node         | Django 웹 서버, MySQL DB, AI 추론, 로그 분석 등          |
| **스토리지 노드 (Storage)**         | 데이터 저장, 복제, 제공               | Ceph OSD, Swift/Object Storage              | EBS, EFS, FSx, S3                           | DB 데이터 파일, 사용자 업로드 이미지, 로그                     |
| **네트워크 노드 (Network/Gateway)** | 트래픽 전달·라우팅                   | Neutron L3/NAT, DHCP Agent                  | VPC, Subnet, NAT GW, ALB/NLB                | 외부 사용자 → 웹 서버 요청 전달                            |
| **가용영역 (AZ)**                 | 물리적 분리로 장애 전파 차단             | Rack/전원/스위치 분리                              | AWS AZ(`ap-northeast-2a`, `2b`, `2c`)       | 한 AZ가 죽어도 다른 AZ에 워크로드 계속 실행                    |
